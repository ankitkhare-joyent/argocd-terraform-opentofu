# 00 · Start here

## What you will build

A small but production-shaped internal platform, on your laptop:

- **OpenTofu** creates a Kubernetes cluster and bootstraps it.
- **Argo CD** then deploys everything else from Git, including itself.
- **OpenBao** stores the secrets; **External Secrets Operator** delivers them
  to the apps, so no secret is ever committed to Git or written to OpenTofu
  state.
- A demo app runs in a `dev` and a `prod` environment, generated by one
  ApplicationSet, promoted by changing one line in Git.

## Prerequisites

- Docker Desktop running. The lab needs about **2 GB** of the Docker VM's
  memory while running, and nothing when stopped.
- [mise](https://mise.jdx.dev) (installs the pinned tool versions).
- `make`, `git`, `curl`, `openssl` (already on macOS).

```bash
cd argocd-terraform-opentofu
mise install
```

## Two ways to run it

**Fast path**: one command, then read the step pages against a running lab.

```bash
make up
```

**Step by step**: run each layer as the matching page describes
(`make cluster`, `make git`, `make bootstrap`, `make bao-login`,
`make openbao-config`).

## Starting and stopping

You'll learn one topic at a time, so the lab is built to pause cleanly:

```bash
make stop    # stops the containers, frees the memory, keeps all data
make start   # resumes; OpenBao unseals itself on the way up
make down    # deletes everything the lab created (not the source files)
make status  # app list and URLs
```

The lab uses its own kubeconfig (`.kube/config` in this folder) and its own
ports, so it doesn't interfere with other clusters or projects on your Mac.

| Service | URL | Login |
|---|---|---|
| Argo CD | http://localhost:48080 | `admin` / `make argocd-password` |
| OpenBao UI | http://localhost:48200/ui | userpass `tofu-admin` / `make bao-password` |
| Gitea (the "GitHub") | http://localhost:43000 | `platform` / `cat .secrets/gitea-password` |
